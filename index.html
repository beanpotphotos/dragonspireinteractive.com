DragonSpire Interactive

An AI game master built like software, not like a prompt.

DragonSpire runs Dungeons & Dragons games inside Fantasy Grounds Unity, in Discord voice and on the web. It works because the AI is only one part of it. A rules engine rolls the dice, databases remember the world, and tested code keeps the game fair.

The problem

“AI Dungeon Master” usually means a chatbot with a costume.

Plenty of players have tried asking a chatbot to run their game. It is fun for ten minutes. Then it forgets hit points, invents dice results, loses the map, contradicts its own world and agrees to anything a player insists on. A language model is a gifted improviser with no memory, no rulebook and no spine. That is a fact about language models, and better prompts do not fix it.

The approach

AI where it is good. Code where it must be right.

JobWho does it in DragonSpireNot the AI because
Rolling dice, applying damage, conditions, spell slots Fantasy Grounds’ own 5E ruleset, driven by FGU Link A model cannot be trusted to do arithmetic or remember rules
Knowing the battlefield, whose turn it is, who has how many hit points The live Fantasy Grounds combat tracker, mirrored into Cory A model’s memory of a fight drifts within minutes
Remembering the world: places, NPCs, quests, and what the party changed Campaign Manager: a database the GM writes in its own web app, read by Cory every turn Model context is short and forgetful
Rules content: D&D 2024 rules and Fantasy Grounds effect codes, each with a trust tier and the extensions it needs DragonLibrary A wrong effect code fails silently in Fantasy Grounds, and models make up the syntax
Fairness: never roll for a player, refuse loot a player just claims, follow turn order Python code with tests A model gives in to a persistent player
Table manners on voice: wait for a pause, stop when talked over, drop stale lines Dee Emma and Cory’s speech triage Needs timing a model does not have

The AI narrates and judges intent. It never decides a die roll.

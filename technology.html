The data services: memory and rules

Campaign Manager, the world’s memory.

The GM writes the world in its own web app: a World Explorer tree of nested places (continent, region, town, tavern) with the NPCs in each, an Adventure Explorer of quests, and public pages players open from links in the chat. Fifteen collections: worlds, campaigns, locations, NPCs with backstories and motives, items, inventories, adventures, quests and quest progress. On every turn Cory hands the AI the party’s surroundings from it: the place, its parent places, what is nearby and who is there. When the party travels, Cory reuses a real place before it invents one. Party state (hit points, sheets, position) never goes there; that belongs to Fantasy Grounds and Cory’s own database.

DragonLibrary, the rules library.

D&D 2024 rules content and thousands of Fantasy Grounds effect codes, the short strings that make Fantasy Grounds automate a spell or feature. A wrong code fails silently, so every code records whether its variants are alternatives (pick one) or parts (apply all), which Fantasy Grounds extensions it needs, and a trust tier from “generated” to “verified at a real table”. When a turn involves an effect, Cory fetches the codes first and keeps only the ones this table’s extensions support. A failed lookup is reported, not guessed.

Where the truth lives

Hexagonal architecture

Cory follows ports and adapters. The core holds the game rules (combat and initiative, party, location and scene, dice, spell slots) and imports only the Python standard library. It reaches databases, AI models, Discord and Fantasy Grounds only through ports, and one composition root wires the adapters in. So a model, a database or a voice engine can be swapped without touching the rules, and the rules can be tested without any of them.

Model adapter: Gemini. Core: unchanged.

The tabletop defines the AI’s abilities

Each time FGU Link connects, it sends Cory the full list of 92 Fantasy Grounds actions and 42 skills. Cory’s tool list is built from it. A new procedure is a Markdown skill file, and a lint step rejects any skill that names an action the engine does not implement.

  • 112 automated tests (97 FGU Link, 15 Cory) and 6 build gates, on every push.
  • Architecture tests fail the build if the core imports an outside library, or if any file not on an approved list calls an AI model.
  • Every Fantasy Grounds command passes a validator before it runs, and returns a receipt after.
  • One authenticated WebSocket between the GM’s PC and the cloud, with sequence numbers and resend after a reconnect, so nothing is lost when the connection drops.
  • Model use is configured per job (game master, scene judge, voice gate, transcription, images), each with a primary, a backup and a timeout. A missing key means unavailable, never borrowed.
